Workflows — data picker

what’s in scope when you reference data, and how it’s shown

The picker shows everything produced before this step on the path that reaches it, grouped by source in run order. The trigger group depends on the trigger; branch siblings and downstream steps are out of scope; a step set to run per item also gets the current item.

When a step runs per item, the current item is in scope here; the whole list is still reachable from the step that produced it.

Scope rules

  • In scope: the trigger/start data, every step that runs before this one on the reachable path, the current item (if the step runs per item), and run context (now, run_id).
  • Always the same order: trigger → upstream steps in run order → the item → run context (last).
  • Out of scope: steps on a different branch, downstream steps, and anything a schedule/manual trigger didn’t carry.
  • Trigger-dependent: Watch → the matched item’s fields (+ via integration); Schedule → ran_at; Manual → the inputs you pass.
  • Shape-dependent: a step with a declared shape lists its fields; an un-shaped output shows a single (whole text) entry; files show as a file.
