# omnideck application v0.1.0-alpha.6

This alpha adds built-in update management and separates the desktop and
container release lifecycles. A desktop release now records the container
version it was tested with, while newer compatible container versions can be
published independently.

## omnideck manages container updates

When a newer compatible version of omnideck's container is published, the
desktop finds it and says so once, quietly, in the corner of whatever you were
doing. You can install it there and then, or leave it until the next time you
open omnideck.

Installing replaces the container software and keeps everything else: your
files, your conversations, and everything omnideck has saved stay exactly where
they are.

Updates are installed automatically by default, and only ever at the moment you
open omnideck, never while you are working. If you would rather be asked each
time, turn that off in Settings.

Every answer is available:

- **Update now** — install it, which takes a few minutes and closes what you
  have open.
- **Later** — install it the next time you open omnideck.
- **Skip this version** — never install this one. The next release asks again.
- **Don't show these again** — stop the notice for good. Updates keep arriving
  and keep installing; Settings becomes the only place they are mentioned.

Settings always shows whether an update is waiting, can install it, and can look
for one without waiting.

Only newer compatible container versions are offered. omnideck never moves
backwards or onto a preview container release.

## omnideck appears in the command line tool

An omnideck installed by this application now shows up in `omnideck list`
alongside any the command line tool set up itself, with its status, its address,
and its logs. Starting and stopping it from there works too.

Both remain valid ways to run omnideck, and neither needs to know about the
other. Nothing about this is visible in the application.

The application also now takes a browser address of its own rather than the one
the command line tool installs on by default, so a computer running both no
longer has the two of them competing for the same one. An omnideck installed by
an earlier release is moved to the new address the first time this one opens,
which takes a few minutes and changes nothing else.

## Fixes

- Repairing an installation could quietly replace it with an older container
  version than the one already there. Repair now treats the version tested with
  this desktop release as a floor, keeping a newer installed version.
- The system notification about an update no longer appears when omnideck is
  already showing you the same thing on screen.
- An update that does not finish preserves both the installed version and the
  requested update, so retrying cannot accidentally install an older version.

## Install

- **Windows 11 x64:** download the `.exe`.
- **Apple Silicon macOS:** download the `.dmg`.
- **Ubuntu, Debian, or Linux Mint x64:** download the `.deb`.
- **Fedora, RHEL, Rocky Linux, AlmaLinux, or openSUSE x64:** download the
  `.rpm`.
- **Other x64 desktop Linux distributions:** download the `.AppImage`.

This preview release is not yet signed. Windows may show a Microsoft Defender
SmartScreen warning and macOS may require Control-clicking omnideck and choosing
Open.

Install this release over an earlier alpha. Preview desktop releases are not
offered automatically.
