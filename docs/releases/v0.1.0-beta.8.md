# omnideck application v0.1.0-beta.8

This beta supersedes v0.1.0-beta.7 with reliable native application zoom in
the desktop packages and the current immutable omnideck CLI release.

## Native desktop zoom

Ctrl/Cmd with `+`, `-`, or `0` now uses the native Tauri webview zoom path on
Windows, macOS, and Linux. This removes the injected CSS zoom controller that
could resize page content without keeping desktop overlays, tab menus, and
embedded previews in the same coordinate system.

Tab action menus remain attached to their opening tab, previews continue to
fill their pane, and resetting zoom restores the native layout.

## Bundled CLI

The desktop packages now pin omnideck CLI `v0.11.0-beta.5` at commit
`f7f70de2caf5`. Every supported sidecar archive, binary, and SBOM remains
locked by its published SHA-256 digest.

## Release safeguards

The disposable Linux and Windows package labs send real VM hardware keyboard
shortcuts for one native zoom step in and out. They record the platform's
observed zoom levels and reject CSS zoom, viewport overflow, iframe viewport
desynchronization, offscreen menus, or a tab menu detached from its anchor.

The exact beta candidate completed install, setup/recovery, hosted boundaries,
zoom, uninstall, and reinstall on Windows, Debian, and Fedora. Native macOS
zoom and layout were also checked manually on the dedicated ARM64 lab host.

## Known limitations

Preview packages do not yet carry paid publisher identities. Windows may show
a Microsoft Defender SmartScreen warning, and macOS may require explicit
approval in Privacy & Security. The physical macOS lab's Accessibility driver
cannot generate a Command-key event that WebKit accepts as a trusted native
zoom shortcut, so that interaction remains an explicit manual check.
