# omnideck application v0.1.0-alpha.5

This alpha rebuilds the setup experience around what setup is actually doing,
adopts the omnideck design language on every screen, and fixes a class of
failure reporting that pointed people at the wrong problem.

## Setup now says what it is doing

Setup shows one line describing the work in progress, above a progress bar that
spans the whole installation rather than the current step. The bar is weighted
by how long each stage really takes, so it moves at a rate that matches the
wait instead of jumping.

Stages that do not apply to your computer are not shown at all. Linux has no
separate environment to prepare, so it moves straight from installing required
software to downloading omnideck's files.

The screens that ask for your password now name what is being installed, so you
can see what you are approving before you approve it.

## Failures say what went wrong

Every kind of setup failure now has its own title and its own guidance, rather
than nine different problems sharing one message.

More importantly, failures are reported as what they are. A problem starting
omnideck was previously liable to be described as an interrupted download —
sending people to check their internet connection over something unrelated —
because the diagnosis was inferred from log text rather than from the step that
actually failed. Setup now reports the step that stopped it, shows how far it
got, and offers the action that resolves that specific problem.

A failure that cannot be attributed to a step no longer blames one.

## Light and dark

The setup and recovery screens now use the same design language as omnideck
itself, in both light and dark, following your system appearance.

## Speed

- The window appears as soon as it can be drawn. Reopening omnideck no longer
  shows nothing at all while the environment is checked.
- Reopening does less work: environment checks that duplicated each other have
  been removed.
- Downloads show real progress instead of an indeterminate bar.
- The Agent Dash screen stops drawing when nothing is moving, so it no longer
  competes with the installation for your processor.

## Updates never interrupt opening

Opening omnideck is never delayed or interrupted by an update, and never
prompts. An installation that is working opens as it is.

## Other fixes

- A warning printed by the container runtime no longer causes setup to fail.
- A port claimed by another program while omnideck was closed is exchanged for
  a free one instead of leaving omnideck unable to start.
- Setup no longer leaves its only button disabled with nothing explaining why
  when an action fails.
- A resumed installation says that finished work was kept.
- The restart screen says your progress is saved and that setup continues by
  itself.
- The recovery download link points at the releases page, which lists preview
  releases.

## Test builds

The release-test scripts gain a host reset for testing a first install without
a fresh virtual machine. It removes only its own isolated test resources and
uninstalls the container runtime, leaving every container, volume, and Linux
distribution belonging to anything else in place. Run it with `--inventory`
first to see exactly what is in scope.

## Install

- **Windows 11 x64:** download the `.exe`.
- **Apple Silicon macOS:** download the `.dmg`.
- **Ubuntu, Debian, or Linux Mint x64:** download the `.deb`.
- **Fedora, RHEL, Rocky Linux, AlmaLinux, or openSUSE x64:** download the
  `.rpm`.
- **Other x64 desktop Linux distributions:** download the `.AppImage`.

This release is not yet signed. Windows may show a Microsoft Defender
SmartScreen warning and macOS may require Control-clicking omnideck and choosing
Open.
